# 六层管线：从一句话到一支 MP4

给教研组讲这套方法时，按这个顺序讲，别人五分钟能听懂"为什么这不是 AI 生成"。

## 谁在干哪件事

| 层 | 谁在干 | 具体职责 | 能不能省 |
|---|---|---|---|
| 画面 | HTML / CSS / SVG | 每个元素的坐标、颜色、字 | 不能（除非改用 Canvas，效果更差） |
| 动作 | GSAP | 一条时间线加补间，谁在几秒出现 | 能，但要自己写缓动，很难看 |
| 摄影 | Chromium 无头 | 按 1/30 秒取景，输出 2700 张位图 | 不能，这是核心 |
| 剪辑 | FFmpeg | 位图序列 + 音轨，编码成 H.264 | 不能 |
| 总控 | HyperFrames | 挂载六镜、lint 质检、doctor 体检、preview 预览、render 调度 | 能，但要自己写调度脚本 |
| 补充 | 本技能自写脚本 | 六镜截图自检、成片参数核对、打包 | 能，但每次要手写 |

**一句话**：HyperFrames 是台印刷机，稿子得你自己写。它不生产任何画面。

## 为什么不能用一个 HTML 写完

六个文件而不是一个，原因有三个，都不是审美问题：

1. **lint 按镜检查**。单文件里六段动画缠在一条时间线上，报错只给行号，定位成本翻倍。
2. **截图自检要能单独挂载**。一镜一文件才能把某一镜 seek 到某一秒截图。
3. **改一镜不碰其它**。用户提"第五镜表格挤了"，只改 `scene-5-table.html`，其余文件零风险。

主文件 `index.html` 只做一件事：声明六镜的 `start`、`duration`、`track-index`，把子组合按时间顺序排好。

## 一次完整生产的时间分布（90 秒片）

| 阶段 | 耗时 | 说明 |
|---|---|---|
| 追问 + 分镜 | 5–10 分钟 | 最容易被跳过，也最不该跳过 |
| 建工程 | 1 分钟 | `init-project.mjs` |
| 写六镜 | 40–90 分钟 | 六镜里通常有两镜（数学推导、表格）占一半时间 |
| lint 修错 | 5–20 分钟 | 第一版几乎必有报错 |
| 六镜截图 + 修改 | 10–30 分钟 | 通常要来回两轮 |
| 渲全片 | 3–5 分钟 | 2700 帧，软件渲染 |
| 抽帧 + 参数核对 | 5 分钟 | |

**第一次做一支片，半天；同主题换数据再做一支，两小时以内。**

## 坐标体系：为什么必须写死

流式布局（flex、百分比）在截图时会随字体加载状态抖动，同一秒两次截图不一致。所以：

- 先定**原点**和**比例尺**：`OX=460, OY=620, S=96`（1 单位 = 96 像素）。
- 所有点由函数算：`px(x) = OX + x*S`，`py(y) = OY - y*S`（y 轴向上）。
- 曲线按采样生成：`for (x = 0.9; x <= 4.25; x += 0.05) push(px(x), py(1/x))`。
- 曲线两端各留一点余量，避免贴边。

换主题时**只改 K 值和采样区间**，坐标体系不动。这就是"换主题两小时"的原因。

## 渲染出的帧去哪了

`render` 在工程内建 `.hyperframes/` 存帧与状态；`--resume` 靠它续渲。**不要手动删这个目录**，除非要重头渲。

## 与其它三支片的关系（同管线不同皮）

| 片子 | 主题 | 皮 |
|---|---|---|
| eq-delta | 判别式 Δ=0 | 白底 90s |
| k-geometry | 反比例 k 的几何意义 | 白底 90s，五轮验收 |
| geo-seasons | 南北半球季节相反 | 纸地图册 60s |
| quad-shift | 二次函数图象平移 | 深夜光轨 90s（深色画风基准） |
| k-geometry-dark | 反比例 深色版 | 深夜光轨 90s（本技能默认皮） |

**同一套管线，换的是皮和数据。** 新主题第一次做，先找一个最像的旧工程当底，比从零写快得多。
