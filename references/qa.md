# 六道自检：执行细则

**lint 只保证结构合规，查不出黑屏、元素缺失、文字溢出、口径错误。** 所以自检必须分六道，各查各的。

## 总表

| # | 查什么 | 机器/人 | 命令 | 通过判据 | 不过怎么办 |
|---|---|---|---|---|---|
| 1 | 结构合规 | 机器判人复核 | `npx -y hyperframes@0.8.181 lint` | 0 错误 0 警告 | 按报错逐条改，改完重跑 |
| 2 | 六镜有画面 | 机器 | `scripts/verify.mjs` | 六镜全出图、无 JS 错误、时间线已注册 | 查 gsap 本地文件、查时间线注册名 |
| 3 | 元素不越界 | 机器 | 同上，看诊断段 | 无溢出条目；字幕距底 ≥80px | 调字号或坐标 |
| 4 | 时序真出现 | 机器出图，人看 | 抽帧拼板 | 每段元素在自称时刻已出现 | 调 start 或补间时刻 |
| 5 | 口径正确 | **只能人做** | 对照 math-rules.md | 七条全过 | 改字幕重渲 |
| 6 | 成片参数 | 机器 | `scripts/inspect-video.mjs` | 分辨率/帧数/时长/码率/体积全达标 | 回第 8 步重渲 |

## 第 1 查：lint

```bash
npx -y hyperframes@0.8.181 lint
```

只看两个数：错误数、警告数。**要 0/0**。警告也要清，因为警告通常对应"这镜的时间轴没注册"这类实际问题。

## 第 2、3 查：六镜截图

```bash
node <技能目录>/scripts/verify.mjs --browser=/usr/local/bin/chromium
```

输出：
- `verify-shots/scene-*.png`（六张，1920×1080）
- 终端报告：每镜 PASS/FAIL + seek 秒数 + 时间线名 + 问题清单

诊断项与含义：

| 诊断 | 含义 | 处理 |
|---|---|---|
| GSAP 未加载 | `assets/gsap.min.js` 缺失或路径错 | 补文件，别改 CDN |
| `window.__timelines` 为空 | 时间线没注册 | 查子组合里的 `window.__timelines['xxx']=` |
| 元素溢出画布 | 有明显位置算错 | 看报告的坐标，通常是负值或超 1920 |
| JS 错误 | 补间属性名写错、变量未定义 | 按报错改 |
| 平均亮度 < 8（深色片） | 疑似黑屏 | 优先查 gsap，其次查路径 |
| 平均亮度 > 250（白底片） | 疑似全白，元素被遮 | 查 z-index 与 opacity |

**逐张自己看**。机器只告诉你"没坏"，不告诉你"对不对"。看四件事：最亮的是不是你想强调的、文字有没有压图形、暗角有没有吃掉边上的字、面积填充能不能看出边界。

## 第 4 查：抽帧拼板

渲出成片后（或对上一版），按整条时间轴抽 16 帧，拼成一张图。

```bash
mkdir -p /tmp/chk && for t in 2 6 9.5 13 20 27 35 42 50 57 62 67 72 78 83 89; do
  ffmpeg -v error -y -ss $t -i <name>.mp4 -frames:v 1 /tmp/chk/f$t.png
done
# 拼 4×4
ffmpeg -v error -y -pattern_type glob -i '/tmp/chk/f*.png' \
  -vf "scale=480:270,tile=4x4" /tmp/chk/board.png
```

看什么：
1. 每个时间点**应该有东西**（没有就是时序错位或有空段）。
2. 关键元素出现在它自称的时刻（例：3.9s 该出第二行字幕）。
3. 转场处没有残留（上一镜的元素不该带到下一镜）。
4. 片尾没有黑尾（最后 2 秒应有画面）。

## 第 5 查：口径（唯一只能人做的）

逐镜把字幕抄出来，对着 [math-rules.md](math-rules.md) 过七条。**这一步不能省，也不能交给脚本**。

实用做法：把六镜的字幕文本按 `grep` 抽出来，逐条打勾：

```bash
grep -o '>[^<>]\{4,\}<' compositions/scene-*.html | sed 's/[<>]/ /g' | head -80
```

## 第 6 查：成片参数

```bash
node <技能目录>/scripts/inspect-video.mjs <name>.mp4 --expect-duration 90
```

判据（90 秒片）：

| 项 | 合格 | 不合格的含义 |
|---|---|---|
| 分辨率 | 1920×1080 | 被降档了，或 `--resolution` 写错 |
| 帧率 | 30 | 影响运动流畅度 |
| 总帧数 | 2700（允许 ±2） | 有帧丢失或时长不对 |
| 时长 | 90.000000 ± 0.05 | 秒级偏差说明帧率算错 |
| 视频码率 | ≥ 1.5 Mbps | **低于 1Mbps 必糊** |
| 体积 | ≥ 10 MB / 90s | 压过头 |

**体积是最好用的经验指标**：90 秒 1080p 正常 15–25MB，只有 5–6MB 就是压过了。

### 第 6 查的两个例外（实测踩过）

**例外一：码率参数不生效。** `hyperframes render --video-bitrate 30M` 输出的仍是 1.8Mbps。想交付真正的清晰版，只能 `--format png-sequence` 渲帧后自己 ffmpeg 编码（CBR 4M）。这条见 SKILL.md 第六节。

**例外二：CRF 会骗过码率判据，也会被码率判据冤枉。** 静止内容多的片子（本技能绝大多数镜头都是"动一下、停几秒"），CRF 12 编码出来是 0.57Mbps / 6.2MB，**画面其实已经接近源帧的锐度**，但 `inspect-video.mjs` 会按"低于 1Mbps 必糊"判 FAIL。反过来，只用 `-b:v 6M` 的 ABR 也只出 1.36Mbps。

所以第 6 查要补一道**目视 1:1**：

```bash
ffmpeg -v error -ss 6 -i out.mp4 -frames:v 1 -y /tmp/f.png
ffmpeg -v error -i /tmp/f.png -vf "crop=760:300:1000:170" -y /tmp/f_crop.png
```

拿这张裁图跟 `pngseq` 的对应源帧、以及上一版成片并排看。判据只有一条：**中文笔画边缘是干净的，还是有块状/振铃/杂色**。有块就是码率不够，干净就是达标——此时脚本报的码率 FAIL 可以判定为误报，但要在交付回复里说明，别悄悄忽略。

最终交付取两者较优：既让脚本 PASS（CBR 4M / 43MB），又不牺牲锐度。


## 什么时候自检可以减配

| 场景 | 可以做几查 |
|---|---|
| 正式交付 | 六查全做 |
| 中间看效果 | 1 + 2（快，30 秒） |
| 只改了一个字 | 2（那一镜）+ 6 |
| 用户催时间 | 1 + 2 + 6，但第 5 查仍要过（口径不能省） |

## 实战踩坑（虚数主题 x²=-4 实测，2026-11）

这一轮从零跑完全链路，六个坑是真撞出来的。每条都附"症状 → 原因 → 改法"，遇到同款直接对照。

| 症状 | 原因 | 改法 |
|---|---|---|
| 某镜左上角冒出半截文字（如"2够不到"），SVG 标签文字消失 | 把 `²` 批量换成 `<sup>2</sup>` 时**连 SVG `<text>` 一起换了**；HTML 标签进 SVG 会让文本节点错位 | SVG 内的上标只用 `²` 字符；`<sup>` 只用在 HTML 图层 |
| 第 3 查报 `#s6-e3 [-13,485,1933,633]` 溢出 | 满宽 1920 的 div 上做 `scale: 1.045` 脉动，放大后超出画布 | 把 scale 挂到 div 内的 `inline-block span`，宽度跟着文字走 |
| lint 报 `gsap_infinite_repeat` | 子组合没有 `data-duration`，`repeat: -1` 会让时长无界 | 改成有限次数：`repeat: Math.floor((总时长-起点)/单周期)-1` |
| 纠错表的删除线横穿整列，盖到右侧列 | 删除线是文字的**兄弟节点**，定位祖先是整列容器 | 把删除线放进目标文字自己的相对定位容器内 |
| verify 起不来：`缺少 playwright-core` | 新工程只由 `init-project.mjs` 建，不装依赖 | 进工程根执行 `npm i playwright-core` |
| lint 报"只能有一个 root index.html" | 工程根留了调试用的临时 html | 调试完立刻删；临时文件放 `/tmp` 或 `.verify-tmp/` |

还有一条不是代码问题，是**分镜节奏**问题：verify 默认 seek 到每镜 60% 处截图，如果这一镜最重要的内容刚好压在 60% 之后（比如第 6.7 秒才出大问句、镜长 10 秒），自检截出来的就是半空的画面。**每镜的核心画面要在镜长的前 60% 内出现**，否则自检看不出问题，成片也会显得"前半段没东西"。

## 用户说"看不清"时：先分清糊在哪一层（2026-11 血泪教训）

这一段是**排查顺序**，不是编码技巧。顺序错了会连着改错三轮。

| 层 | 现象 | 是不是片子的问题 | 怎么判 |
|---|---|---|---|
| ① 聊天页面/公众号里的**内嵌预览播放器** | 手机上竖屏小窗看，糊 | **不是**。播放器按小窗尺寸降采样、还可能自动降码率 | 让用户下载到手机相册、用本地播放器再看 |
| ② 下载后的**本地播放器** | 相册里看清晰 | 不是 | 这一条成立就说明文件本身达标，到此为止 |
| ③ 本地播放也糊 | 全屏看仍然软 | **是** | 才轮到查码率、分辨率、1:1 裁图 |

**实测事实（虚数 x²=-4 那支片）**：交付文件 3.99Mbps / 1080p / 2700 帧，从 CDN 下载回来跟母版**字节一致**（45,192,534 字节，没有被平台转码）；用户在手机页面小窗看觉得糊，下载到相册看就清晰。也就是说，前两轮我按①去改编码（`--video-bitrate`→PNG+CBR→CRF），全是无效功。

**规矩**：用户第一次说"糊"，第一句先问"你是在哪儿看的"——页面预览 / 下载后相册 / 电脑播放器。这一句能省两小时返工。

顺带记住一个物理事实：手机竖屏小窗显示 16:9 视频时画面只有约 390px 宽，缩放比 0.20，片上 26px 的字实际只有 5px 高。**这是尺寸问题，不是清晰度问题**，码率给到 20Mbps 也救不了。真要在小窗可读，只能靠字号（见 [visuals.md](visuals.md) 的"手机可读线"），那是版式层面的活。

**交付话术**（每次交付都带一句）："页面里那个是预览，会糊；下载到相册看原片才是真实画质。"

## 常见"自检过了但片子还是不能交"


| 现象 | 自检没覆盖到的原因 |
|---|---|
| 公式对了但读起来别扭 | 第 5 查只看口径，不看语感——要人工读一遍 |
| 每镜单独好看，连起来乱 | 六镜各自过，但缺"整体节奏"检查——看拼板 |
| 静态好看，动起来晃 | 截图是定帧，看不出补间问题——抽帧看相邻两帧 |
| 学生看不懂 | 口径对但讲法超纲——这是受众问题，自检管不了，要老师判断 |
